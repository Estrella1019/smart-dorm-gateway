# 五人模块交接

## 考前组长交付

已有目录结构、配置、协议编解码、TCP 接入、模拟灯、CLI 控制、测试和 GitHub 测试配置。先完整跑一遍 README，再共同阅读协议。当前骨架包含最小执行确认和超时返回，尚未完成课程所要求的完整可靠控制。

| 负责人 | 开发入口 | 考后交付与验收 |
|---|---|---|
| 组长 | shared/、gateway/server.py | 保持公共接口稳定，补 UDP 与连接保护，合并集成；TCP/UDP 同时接入 |
| 组员 1 | devices/light.py，新建其他设备 | 灯、门锁、温湿度；心跳、重连、去重、异常开关；同请求重发不重复执行 |
| 组员 2 | gateway/services.py、registry.py、server.py 控制逻辑 | 在线/离线状态、超时重试、每设备队列；保留 request_id，确认丢失后正确处理 |
| 组员 3 | web/，新增网关 HTTP/WebSocket 适配器 | 设备列表、实时数据、控制和反馈；网页操作能收到设备执行结果 |
| 组员 4 | 新建 gateway/storage.py、测试工具 | 事件/指令持久化、查询、批量设备和异常实验；按 request_id 追踪，提供可复现实验 |

## 建议任务单

### 组员 1

1. 先复用 light.py 跑第二个设备，确保编号不冲突。
2. 与组长约定 UDP 数据格式，与组员 2 约定心跳、重连和去重窗口。
3. 增加温湿度模拟器与门锁，不改动底层公共分帧逻辑。
4. 增加模拟响应延迟、丢弃确认的参数，供组员 4 使用。

### 组员 2

1. 将当前 submit_command 骨架整理为控制服务，现有测试先保持通过。
2. 增加离线状态保留与心跳超时；区分 TCP 断线和长期无有效上报。
3. 同一逻辑指令的多次发送必须复用 request_id；与组员 1 联调去重。
4. 用有上限的队列替代当前 device_busy 拒绝策略，明确超时与排队顺序。

### 组员 3

1. 先给 list_devices/submit_command 加 HTTP 适配，不直接读取 Socket。
2. 页面只做列表、状态、按钮和执行结果；先用模拟返回值并行开发。
3. 订阅事件经 WebSocket 推送，页面重连后先查询最新快照。
4. 与组员 4 合作暴露日志查询，避免重复写数据库层。

### 组员 4

1. 订阅 EventBus，通过队列批量写 SQLite；数据库放 data/（已忽略）。
2. 定义日志查询函数供组员 3 调用，保留 request_id 关联。
3. 复用组员 1 的设备程序，新增批量启动脚本，不维护第二套协议实现。
4. 记录环境、设备数、频率、确认延迟、成功率和资源占用；说明测量方法。

## 协作规则

- 每人负责自己的实现、测试和报告章节；组长负责整合，不包办修复。
- 11 月 8 日交接后，每两天提交一次可运行增量；用短分支和 Pull Request 合并。
- 提交前运行 unittest；协议、配置和服务签名变更要同步更新样例、文档与测试。
- 共享文件由组长协调修改；组员 2 改 server.py 前先沟通，尽量抽取模块降低冲突。
- 当前课程方案、课堂照片与组员身份资料不在源码目录中；公开仓库仅提交需要公开的项目材料。
